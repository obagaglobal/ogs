# OWASP ASVS Level 2 review — Phase 3 (authentication, sessions, access control)

**Scope:** API `apps/api` and web shell `apps/web` as of Phase 3B. **Standard:** OWASP ASVS **4.0.3**, chapters V2 (Authentication), V3 (Session Management) and V4 (Access Control), Level 2. This is the numbering used by the [Phase 3 plan](../plans/phase-3-identity.md) §5.
**Method:** self-assessment by the implementer, backed by automated tests where a test exists. This is not an independent audit. An external penetration test is planned for Phases 15–17.

> ASVS 5.0 (2025) renumbers these chapters. Re-mapping this checklist to 5.0 is a follow-up item (F-6).

Legend: ✅ met · 🟡 partly met (see note) · ⏳ not yet (planned phase) · n/a not applicable.

## V2 Authentication

| ASVS 4.0.3 section                  | Status | How OGS meets it                                                                                                                                                                                                                                                                                                                                                                                                                                                   | Evidence                                                             |
| ----------------------------------- | ------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------- |
| V2.1 Password security              | 🟡     | 12–128 Unicode code points; no composition rules, truncation or forced rotation. Pasting and password managers work, and the web inputs use `autocomplete`. Passwords are NFKC-normalised before hashing. They are checked against a breached-password list, but only an offline list (the NCSC top 100k, 1,210 entries long enough to matter). The online HIBP check is off until a data-protection review (P3-4). **No strength meter in the web UI yet** (F-1). | `packages/contracts/src/auth.test.ts`, `password-policy.test.ts`, A1 |
| V2.2 General authenticator security | 🟡     | Per-account and per-IP rate limits, which fail closed. Progressive lock after 5 failures, 15-minute lock and owner email after 10. MFA is mandatory for platform staff and admin roles. **The owner is not yet emailed after a password change or reset, or when MFA is turned on or off** (F-2).                                                                                                                                                                  | A4, B2, `rate-limiter.test.ts`                                       |
| V2.3 Authenticator lifecycle        | ✅     | Self-registration with email verification. Recovery codes are shown once, at enrolment. No default passwords: seed passwords are local-only and refused in production.                                                                                                                                                                                                                                                                                             | A1, B1                                                               |
| V2.4 Credential storage             | ✅     | Argon2id (19 MiB, t=2, p=1, 16-byte salt) via `node:crypto`, checked against the RFC 9106 vector. Parameters are stored with each hash and upgraded on login.                                                                                                                                                                                                                                                                                                      | `password-hasher.test.ts`, A3                                        |
| V2.5 Credential recovery            | ✅     | Single-use 256-bit reset token, valid 30 minutes, stored only as SHA-256 and sent as a URL **fragment**. Identical answers whether or not the account exists. A reset signs out every session.                                                                                                                                                                                                                                                                     | A1, A2, A11                                                          |
| V2.6 Look-up secret verifier        | ✅     | 10 recovery codes of about 49 bits each, stored as SHA-256 and consumed atomically, each usable once.                                                                                                                                                                                                                                                                                                                                                              | B1                                                                   |
| V2.7 Out-of-band verifier           | n/a    | SMS or push second factors are deliberately not offered (P3-5).                                                                                                                                                                                                                                                                                                                                                                                                    | —                                                                    |
| V2.8 One-time verifier (TOTP)       | ✅     | RFC 6238 (checked against the RFC vectors), ±1 time step, and a code is never accepted twice. Secrets are sealed with AES-256-GCM under a rotating keyring, and the development key is refused in production. Rate limited.                                                                                                                                                                                                                                        | `totp.test.ts`, B1                                                   |
| V2.9 Cryptographic verifier         | n/a    | WebAuthn / passkeys come after v1.                                                                                                                                                                                                                                                                                                                                                                                                                                 | —                                                                    |
| V2.10 Service authentication        | 🟡     | No secrets in code: credentials come from validated environment variables. The API runs as `ogs_app`, which cannot bypass RLS. **Production secret storage** (vault, rotation) is decided in Phase 15 (F-3).                                                                                                                                                                                                                                                       | `env.test.ts`, T4                                                    |

## V3 Session management

| ASVS 4.0.3 section                     | Status | How OGS meets it                                                                                                                                                                                                                          | Evidence                                    |
| -------------------------------------- | ------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------- |
| V3.1 Fundamental session security      | ✅     | The session token never appears in URLs. Email tokens travel in URL fragments, which are not sent to servers.                                                                                                                             | A11                                         |
| V3.2 Session binding                   | ✅     | Opaque 256-bit id, generated server-side and stored only as SHA-256 in Redis. A new session on every sign-in, and the id rotates after MFA and on password change.                                                                        | A5, B1                                      |
| V3.3 Session termination               | ✅     | 30-minute idle and 12-hour absolute timeouts. Logout invalidates the session server-side. Users can sign out other devices, and password reset or change signs out everything else. Suspended users are signed out on their next request. | A5, A10                                     |
| V3.4 Cookie-based session management   | ✅     | `HttpOnly`, `SameSite=Lax`, `Path=/`, no `Domain`. In production the cookie is `Secure` with the `__Host-` prefix, and env validation refuses otherwise.                                                                                  | A7, `session-cookie.test.ts`, `env.test.ts` |
| V3.5 Token-based session management    | n/a    | No bearer tokens or JWTs (ADR-011).                                                                                                                                                                                                       | —                                           |
| V3.6 Federated re-authentication       | n/a    | No SSO or federation.                                                                                                                                                                                                                     | —                                           |
| V3.7 Defences against session exploits | ✅     | Re-authentication (TOTP step-up within 15 minutes) before changing a password, regenerating recovery codes, disabling MFA and elevating to platform access. Per-session CSRF token on every unsafe request, plus JSON-only bodies.        | B2, B3, A6                                  |

## V4 Access control

| ASVS 4.0.3 section                       | Status | How OGS meets it                                                                                                                                                                                                                                                          | Evidence   |
| ---------------------------------------- | ------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------- |
| V4.1 General access control design       | ✅     | Default deny: the API does not start if any route lacks an access rule. Permissions are enforced on the server and reloaded on every request. Tenant isolation is enforced again by PostgreSQL RLS.                                                                       | A8, T1–T12 |
| V4.2 Operation-level access control      | ✅     | Another tenant's id returns 404; a foreign or forged workspace returns 403; ended memberships and removed roles stop working on the next request. CSRF is covered under V3.7.                                                                                             | A10        |
| V4.3 Other access control considerations | 🟡     | MFA is mandatory for administrative roles. Cross-tenant staff access requires an explicit elevation with a reason; it lasts 15 minutes and is fully audited. **Directory browsing and metadata exposure** (NGINX, object-store hardening) are reviewed in Phase 15 (F-4). | B3, B4     |
